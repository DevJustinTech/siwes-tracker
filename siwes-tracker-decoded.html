The big picture

Two minutes of groundwork so every line after this makes sense.

Your project is a web app — a program you use through a browser instead of by double-clicking a file. It does one job: let a student on industrial training log what they did each working day, and show it back as a tidy log book.

It's actually two apps that share one brain-storage:

Youbrowser
→
PHP pagesthe app you see
→
MySQLthe filing cabinet
Other programslike a phone app you might build later
→
FastAPIPython twin, no visible pages
→
MySQLsame cabinet

Both apps read and write the exact same two tables. Log a day in one, it appears in the other.

› How a website actually works

  • 1. Your browser sends a request: "please give me the page at this address".
  • 2. A program called a server receives it. Here that's Apache (from XAMPP) or PHP's built-in server.
  • 3. The server runs the PHP file like a recipe: it checks the database, does sums, and mixes a finished HTML page.
  • 4. Only the finished page travels back. The browser never sees the recipe — just the dish.

› The six mini-languages in this project

③ SQL — talking to the filing cabinet

The language MySQL (the database) understands. Four verbs run this whole project:

The ? in WHERE id = ? is a prepared statement slot: the value is filled in separately, so a sneaky user can't type SQL of their own into a form box (that trick is called SQL injection — the app blocks it everywhere).

Describes how things look: colours, sizes, spacing. Pattern: selector { property: value; } — "for everything matching this nickname, style it like this". Full primer in Part 7.

/** Currently logged-in student row (cached) */
function current_student(): ?array
{
    static $student = null;
    static $loaded  = false;
    if (!$loaded && is_logged_in()) {
        $stmt = db()->prepare('SELECT * FROM students WHERE id = ?');
        $stmt->execute([$_SESSION['student_id']]);
        $student = $stmt->fetch() ?: null;
        $loaded  = true;
    }
    return $student;
}

/** One-shot flash messages */
function flash(string $key, ?string $message = null): ?string
{
    if ($message !== null) {
        $_SESSION['flash_' . $key] = $message;
        return null;
    }
    $value = $_SESSION['flash_' . $key] ?? null;
    unset($_SESSION['flash_' . $key]);
    return $value;
}
What it says

current_student(): fetches the full row of the logged-in student from the database. ?array = "a labelled list, or nothing". Again static: fetch once per page, then remember — so five different spots on a page can ask without five database trips. Notice the ? slot and execute([...]) pattern — the safe prepared-statement way of putting your ID into the query.

flash(): those little green "Entry updated ✓" messages. The trick: page A saves the message in the session, sends you to page B, and page B shows it once and deletes it (that's the unset). That's why refreshing never shows a stale message twice. The same function stores messages (with a second argument) and reads them (without).

PHPlines 80–103
/** CSRF token (create + return) */
function csrf_token(): string
{
    if (empty($_SESSION['csrf_token'])) {
        $_SESSION['csrf_token'] = bin2hex(random_bytes(32));
    }
    return $_SESSION['csrf_token'];
}

/** CSRF hidden input for forms */
function csrf_field(): string
{
    return '<input type="hidden" name="csrf_token" value="' . e(csrf_token()) . '">';
}

/** Verify CSRF on POST requests — call before handling any POST */
function csrf_verify(): void
{
    $token = $_POST['csrf_token'] ?? '';
    if (!is_string($token) || !hash_equals($_SESSION['csrf_token'] ?? '', $token)) {
        http_response_code(419);
        exit('Page expired — please go back and try again.');
    }
}
The CSRF guard, in three pieces

CSRF ("Cross-Site Request Forgery") is this attack: you're logged into the tracker in one tab; in another tab, an evil page has a hidden form that quietly submits "delete my entry" to the tracker as you. The browser attaches your session cookie automatically, so the tracker can't tell it wasn't you.

The fix — a secret handshake: csrf_token() invents a 64-character random string (line 84: 32 random bytes written as hex) and keeps it in your locker. csrf_field() hides it inside every real form. csrf_verify() runs whenever a form is submitted: "did the form bring the exact secret only our page could have put there?" The evil page doesn't know the secret, so its sneaky submission fails with error 419.

hash_equals() compares the strings in a way that leaks no timing hints — the professional touch.

/** Friendly "Wed 09 Sep 2026" day label */
function day_label(string $date): string
{
    return date('D d M Y', strtotime($date));
}

/** SIWES week number since the student's first entry (min 1) */
function siwes_week_number(array $student, string $date): int
{
    $stmt = db()->prepare('SELECT MIN(entry_date) FROM log_entries WHERE student_id = ?');
    $stmt->execute([$student['id']]);
    $first = $stmt->fetchColumn();
    if (!$first) return 1;
    $weeks = (int)floor((strtotime($date) - strtotime((string)$first)) / 604800);
    return max(1, $weeks + 1);
}
The date helpers

day_label(): turns "2026-09-09" into the pretty "Wed 09 Sep 2026" you see in the tables. strtotime converts the stored date into a timestamp (a count of seconds since 1970 — computers prefer counting seconds), and date('D d M Y') formats it back with the weekday (D), day, month, and year.

siwes_week_number(): even in a daily log book, supervisors love week numbers — so this asks the database "what's the earliest day this student ever logged?" (MIN = smallest value). Then: seconds between this day and that first day, divided by 604800 (the number of seconds in 7 days), rounded down = how many weeks in. max(1, …) means "never answer less than 1" — Week 1, not Week 0. That's what prints the little "Week 3" under each entry.

What it says

One function, two parts:

def create_access_token(subject: str) -> str:
    expires = datetime.now(UTC) + timedelta(minutes=settings.access_token_expire_minutes)
    payload: dict[str, Any] = {"sub": subject, "exp": expires}
    return jwt.encode(payload, settings.jwt_secret, algorithm=settings.jwt_algorithm)

def decode_access_token(token: str) -> str | None:
    try:
        payload = jwt.decode(token, settings.jwt_secret, algorithms=[settings.jwt_algorithm])
        sub = payload.get("sub")
        return str(sub) if sub is not None else None
    except jwt.PyJWTError:
        return None
What it says

What a JWT is: a tamper-proof name-tag. It carries visible text — {"sub": "5", "exp": …} ("this is student 5, valid until…") — plus a signature made with the server's secret ink. Read it: yes. Alter it: the signature no longer matches and it's rejected. So the server can trust "this is student 5" without storing any session.

create stamps the payload + expiry and signs it. decode checks the signature and expiry; any problem (forged, expired, garbled) is caught and becomes None — the caller then rejects the request. The str | None return type says exactly that: "a string, or nothing".
